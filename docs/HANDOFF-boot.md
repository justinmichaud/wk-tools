# HANDOFF — the boot substrate: what is left

- [ ] build moose's bench mode (docs/Urgent/HANDOFF-moose-bench.md) [needs moose]
- [ ] rpi4: why the kernel buildroot builds from the release-pinned rpi-5.15.y tree never reaches userspace on that board. Measured 2026-08-31 by staging one kernel at a time over the tryboot lane with everything else held identical -- a Raspberry Pi published kernel boots it, the built one does not, not even with the known-good device tree and no display overlay, and the built config lacks nothing a Pi 4 needs (ARCH_BCM2835, MMC_SDHCI_IPROC, PCIE_BRCMSTB, LPAE, HIGHMEM, SMP). What is left is the 2020.02 fork's gcc 9.2. The profile pins a kernel instead (BR_KERNEL_DEB_URL), so this is a question, not a blockage; answering it needs a serial console at the board, since the hang is before any console the network can carry [needs the rpi4 and a USB-serial adapter]
- [ ] a profile that pins its kernel still builds one it throws away (BR2_LINUX_KERNEL stays on, so the image carries two module trees). Turning the kernel build off is the honest shape; it was left on because the failure mode of getting it wrong is an image that assembles with no kernel, and that costs a board trip to discover [needs one image build to verify]
